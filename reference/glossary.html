📖 Glossary

Quick-reference definitions for every concept in this course. Bookmark this page — you'll come back often.

JMS & Messaging Core
JMS (Java Message Service)

A Java API standard (JSR 343 / Jakarta Messaging 3.1) that defines how Java applications send, receive, and process messages. Think of it as JDBC but for messaging instead of databases.

Message Broker

A server that receives messages from producers and routes them to consumers. ActiveMQ Artemis is a message broker. It sits between services so they don't need to know about each other.

Queue (Point-to-Point)

A destination where each message is consumed by exactly one consumer. If three consumers listen on the same queue, each message goes to only one of them (load-balanced). Use for: task distribution, work queues.

Topic (Publish/Subscribe)

A destination where each message is delivered to all active subscribers. If three consumers subscribe to a topic, all three receive every message. Use for: event broadcasting, notifications.

Producer / Publisher

The component that creates and sends messages to a queue or topic.

Consumer / Subscriber

The component that receives and processes messages from a queue or topic.

ConnectionFactory

A JMS object that creates connections to the broker. In Spring Boot, this is auto-configured — you rarely touch it directly.

Message

The unit of data sent through JMS. Has three parts: headers (metadata like destination, timestamp), properties (custom key-value pairs for filtering), and a body (the actual payload — text, bytes, map, object, or stream).

Destination

The named endpoint (queue or topic) where messages are sent and received. e.g., order.queue or price.updates.topic.

Spring Boot JMS
JmsTemplate

Spring's high-level helper for sending JMS messages. Handles connection management, error conversion, and message creation. The send(), convertAndSend(), and sendAndReceive() methods are your primary tools.

@JmsListener

Annotation that marks a method as a JMS message consumer. Spring automatically wires up a listener container that polls the destination and calls your method for each message.

JmsListenerContainerFactory

Factory that creates and configures the listener containers used by @JmsListener. You customize this when you need specific concurrency, acknowledgement modes, or topic subscription behavior.

MessageConverter

Converts between Java objects and JMS messages. Spring's MappingJackson2MessageConverter serializes POJOs to JSON and back. Essential for sending structured data.

spring-boot-starter-artemis

The Maven/Gradle dependency that auto-configures Spring Boot to work with ActiveMQ Artemis. Provides a ConnectionFactory, JmsTemplate, and JmsListenerContainerFactory out of the box.

ActiveMQ Specifics
ActiveMQ Artemis

The modern, high-performance successor to ActiveMQ 5.x (Classic). Built on Netty for non-blocking I/O. Native Spring Boot 3 support. Supports AMQP 1.0, MQTT, STOMP in addition to JMS.

ActiveMQ Classic (5.x)

The original ActiveMQ broker. Still widely used in legacy enterprise systems. Development has slowed in favor of Artemis. No full embedded broker support in Spring Boot 3.

Dead Letter Queue (DLQ)

A special queue where messages land after they fail processing too many times. Prevents poison messages from blocking a queue. Default in Artemis: DLQ. Configurable per address.

Durable Subscriber

A topic subscriber that survives disconnection. The broker stores messages while the subscriber is offline and delivers them when it reconnects. Requires a unique clientId + subscriptionName.

Address (Artemis)

Artemis's unified abstraction for destinations. An address can behave like a queue (anycast routing) or a topic (multicast routing), depending on configuration.

Embedded Broker

An ActiveMQ instance running inside your Spring Boot application (same JVM). Perfect for development and testing. Enabled by adding artemis-server dependency and setting spring.artemis.mode=embedded.

Spring Profiles
Spring Profile

A named set of configuration that is activated at runtime. Beans and properties can be tied to a profile so they only load when that profile is active. Common profiles: dev, test, staging, prod.

application-{profile}.yml

Profile-specific properties file. When a profile is active, Spring loads both application.yml (shared) and application-{profile}.yml (profile-specific). Profile-specific values override shared ones.

@Profile

Annotation that makes a bean, configuration, or component available only when a specific profile is active. e.g., @Profile("dev") means the bean only loads in dev mode.

Profile Group

A Spring Boot feature that lets you activate multiple related profiles under one name. Defined in application.yml under spring.profiles.group. e.g., activating "production" could automatically activate "prod" + "metrics" + "ssl".

spring.profiles.active

The property that controls which profile(s) are active. Can be set via CLI (--spring.profiles.active=prod), env var (SPRING_PROFILES_ACTIVE=prod), or in application.properties.

Advanced Patterns
Request-Reply

A synchronous communication pattern over JMS. The producer sends a message and waits for a response on a temporary queue. Spring's JmsTemplate.sendAndReceive() implements this.

Message Selector

A SQL-like filter string that lets a consumer receive only messages matching certain header/property conditions. e.g., "priority > 5 AND region = 'APAC'". Evaluated broker-side.

CachingConnectionFactory

A Spring wrapper around ConnectionFactory that caches sessions, connections, and producers for better performance. Essential for production. Replace the raw factory with this.

Acknowledgement Mode

Controls when a message is considered "consumed." AUTO_ACKNOWLEDGE (default): acknowledged when listener returns. CLIENT_ACKNOWLEDGE: your code must call message.acknowledge(). SESSION_TRANSACTED: acknowledged on transaction commit.
